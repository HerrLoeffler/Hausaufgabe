The fixture runs the current integration GradeCrew HTML, CSS, renderer functions and locale translator in a real WKWebView. It tests logical CSS viewports; changing a viewport does not establish coverage of that device's hardware or OS version.

Build without network or credentials:

```sh
python3 native/GradeCrewTeacher/LayoutTests/Web/prepare_web_fixtures.py --output /private/tmp/gc-layout21-fixture
node --test native/GradeCrewTeacher/LayoutTests/Web/test_web_fixtures.cjs native/GradeCrewTeacher/LayoutTests/Web/test_geometry_rules.cjs
```

Serve the output using the XCTest host's `gc-layout://fixture/index.html` scheme. Its `WKScriptMessageHandler` must provide `webkit.messageHandlers.gradecrewNative`; the native presentation scripts use the fixture's `location.origin` solely for this offline fixture. The original native resource files keep their production origin guards.

Queries:

- `screen=workspace|settings|editor`
- `lang=de|en`, `role=teacher|admin`
- `type=single|multi|text|dropdown|truefalse|gapfill|matching|ordering|grouping|markwords|number|all`
- `variant=default|longtext|media|readonly`. Media includes real image/audio fields and expands both native media sections plus the audio editing sections. Readonly uses the renderer's published-test lock.

Wait for `window.gcLayoutReady === true`. Evaluate `window.gcLayoutAudit()`; it returns `{issues:[{rule,selector,detail}],metrics:{...}}`. Script failures are issues, including failures that happen before readiness. `window.gcLayoutAuditSelfTest()` temporarily introduces horizontal overflow and a 31 pt primary-action offset, verifies both are detected, then restores the DOM. It also inserts a 12 pt associated checkbox label to prove the target check catches it, then moves the real Coco launcher over a real publication-toggle label to prove `control-occluded`; the forced-overlay probe temporarily moves the original launcher to body to escape backdrop-filter containing blocks, then every probe restores the exact parent/sibling, scroll and styles. Run it inside real WKWebView. Node/jsdom tests validate rendering, locales, roles, readonly state and media expansion; they make no geometry claims.

Geometry checks cover document/element horizontal overflow, missing images, static text clipped by a hidden/clip ancestor, selected language/question-type text width, 44 pt targets on actual buttons/selects/summaries/text fields and every radio/checkbox's associated visible labels (falling back to the original control when no visible label exists), overlaps within real control rows, tutorial/new-test centering, equal metric gaps, question → answers → media order, and actual hit-test occlusion of controls by the shared floating Coco launcher. Long authored values inside text inputs/areas intentionally scroll. Descendants of explicit overflow:auto/scroll containers are distinguished from page overflow; their containers remain checked. Occlusion samples already behind an active sticky/fixed heading are recorded as `metrics.paintClips` only when the launcher is natively docked with static positioning, the header background is at least90% opaque, its sticky top is pinned, and the real hit stack paints that header above the target. Floating launchers, transparent headers, ordinary flow overlap and reversed stacking still fail. There are no fixture-only layout corrections or global overflow suppression.

`Source/provenance.json` records every pinned file's SHA256. Four byte-identical tracked repository files are referenced by `repositoryPath` instead of vendored again; the generator validates their expected hashes before copying and fails on drift. Other current integration assets differ from the older tracked artwork and remain pinned. Its teacher app HTML is /workspace.html; /index.html is now the public homepage and cannot supply the dashboard fixture. Generated `provenance.json` also records individual renderer hashes and the current native presentation-resource hashes.
