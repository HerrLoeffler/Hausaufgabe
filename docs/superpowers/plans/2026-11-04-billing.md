# GradeCrew Billing Implementation Plan — Vorschlag, nicht zur Ausführung freigegeben

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after a concrete implementation authorization. Steps use checkbox (`- [ ]`) syntax for tracking. Keine automatische Delegation, Kontoeröffnung, Preisaktivierung oder Deploymentbefugnis aus dieser Datei.

**Goal:** Einen fairen kostenlosen Einstieg und einen belastbaren persönlichen/ersten institutionellen Webzahlungsbetrieb nach Martins noch offenen Entscheidungen umsetzen.

**Architecture:** Firebase Auth identifiziert UID; serverseitige Providerintegration verarbeitet Käufe und signierte Ereignisse. Eine servergeschriebene Berechtigungsprojektion steuert Nutzung, ein separates Operations-/Kostenledger begrenzt KI und schützt laufenden Unterricht. Externes Checkout/Portal und ein führender Rechnungsweg reduzieren sensible Eigenverarbeitung.

**Tech Stack:** vorhandenes Vanilla-JavaScript-Web, CommonJS Functions auf Node22, Firestore `(default)`, bestehende Assessmentfunctions, später bestehende native Swiftclients. Provider-SDKversion vor Umsetzung aktuell prüfen/pinnen; heute nichts installieren.

**Spec:** [Entscheidungsbericht](../../billing/2026-11-04-entscheidungsbericht.md), besonders Abschnitte4–10 und Abnahmematrix14. Task GC-BILLING-PLAN-01; Planungsstatus `plan_only`, kein Startsignal.

- Aktuelles main START_HERE/AGENTS/STATE/TODO/Registry und vorhandene Owner/HDF vor Fortsetzung frisch lesen; dieselbe Task-ID erhalten.
- Vorliegende Preise/Kontingente/Nachfristen sind Vorschläge. Offene Nutzer-/Rechts-/Providerentscheidungen nicht als beschlossen ausgeben.

- Keine Schülerdaten an PSP/Marketing, keine Geheimnisse/Bank-/Steuerunterlagen ins öffentliche Repo.

## Review Focus

1. Zwei gleichzeitig kaufende Geräte, doppelte/verspätete Providerereignisse und verlorene Rücksprungseite dürfen keine Doppelbelastung/-berechtigung erzeugen.
2. Abo-/Sitzablauf mitten im Unterricht und verzögerte Offlineabgabe dürfen erlaubte Schülerleistungen nicht zerstören.
3. Unbekannter Providerverbrauch nach Timeout darf keine blinde Wiederholung oder unverdiente Kostenfreigabe auslösen.
4. Private Lehrkraft, Schule und anderer Tenant müssen selbst bei gleicher E-Maildomain und manipulierten IDs sauber getrennt bleiben.
5. Anbieter-/Steuer-/Applestatus und Jahresverlängerung müssen zur sichtbaren Vertragsbeschreibung passen; grüner Techniksandboxlauf ist keine Rechtsfreigabe.
