# One question, one bounded experience

Read current project rules, role/owner, actual task handoff and existing prototype evidence. This skill gives coordinators only the ability to brief/assess; building, starting processes, tests and cleanup belong to the authorized specialist. No new deployment, provider spend or engine choice follows from a prototype request.

Name the concrete unresolved question, what observation could answer it, the smallest allowed surface and a stopping limit. Existing product choices remain fixed. Distinguish a layout comparison, a portable logic question and a question about the real target runtime. Use the [probe contract](references/probe-contract.md).

For Unreal camera, movement, spatial route, animation, save/resume or native input questions, prepare/use the existing native Unreal build, scene and harness. HTML may explain abstract logic but is not evidence of native behavior or game feel. If the target runtime is unavailable, record the exact missing prerequisite and leave the question unresolved. Web work preserves existing GradeCrew components/tokens and framework; only relevant available frontend/Figma skills are aids, not mandatory invented dependencies.

Prefer one existing slice. Use at most two bounded alternatives when a real preference remains open; isolate experimental flags/files/slots from production and personal saves. A save-position comparison preserves validated learning state, SafeLoad and gate boundaries; do not introduce a database or save migration unless explicitly assigned. Keep regression/safety checks needed for the probe; do not inherit a blanket “no tests” rule.

Record exact source/build, start state, user action and visible state/side effect. Before desktop input bind the process and unique window you actually started; a shared application bundle ID is insufficient. Leave other games/editors and user data untouched. Clean up only owned test resources and retain evidence.

Hand over the run entry and question for Martin via the authorized coordinating route. Record the actual human verdict, rejection or pending response; a recommended default is not an answer. Then reference the validated choice in the existing task and authorize ordinary implementation separately as needed. A green build, screenshot or finished prototype is not a device/learning/deploy acceptance. Apply current effort rules and preserve recovery/budget IDs.
