# Two-axis record

Existing task, author intent vs approved criterion source, role/owner, exact base/head, scope, source files and review identity/method.

Spec: criterion → observed implementation/evidence → met/partial/missing/not checked → actionable finding or bounded conclusion.

Standards: concrete repo rule/contract → changed file/line → observed breach or judgment → impact and evidence; tools already enforcing it are named, not reinvented.

Keep the axes separate, including missing criteria and independence limits. User-facing result: concrete behavior, per-axis conclusion, exact performed vs reported tests, remaining checks, one next owner action. No unearned product/Security/merge/deploy approval.

PR explanation: triggering case; before → after; exact evidence; scope and rollback tradeoff. Prefer prose for small changes; diagram only when it clarifies.
